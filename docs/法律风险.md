> 写于 2026-10-21。给产品决策用，不是律师意见。
> **当天已从工作区删掉站点级文档和示例。** OCR 等库代码还在，公开 README、示例和技能文档不再写用法。新的公开示例是 `examples/cdp/own_site.rs`（本地页 + apizero.cn 公开文档）。下面第 1 节是删除前的清单，用来对账；那些路径现在不应该还在工作区里。历史 git 提交里仍然有旧文件。

## 1. 现在仓库里实际有什么

公开定位（README、CSDN 0.6.2 稿）讲的是：Rust 控本机 Chrome、给 Agent 一份短大纲、登录态落在磁盘 Profile。这条线是通用浏览器自动化，和 Playwright / Puppeteer 同一类。

同一仓库里还有另一层，而且写进了文档、示例和 crates.io 关键词（`captcha` / `ddddocr` / `anti-detect`）：

| 公开产物 | 它实际在做的事 |
|---|---|
| `examples/clickword/yidun_*`、`docs/OCR模型热替换.md` | 针对网易易盾点选：取图、OCR、拟人轨迹、提交，并用 `YIDUN_HARVEST` 把过盾样本存下来 |
| `slider` feature | 滑块缺口（含极验、顶象） |
| `examples/cloudflare/`、`docs/CF协议过.md`、`docs/CDP过盾.md` | 对 `auth.exa.ai` 的 Turnstile 出 token，并写到验证接口返回成功；另有一套不开浏览器抠 VM 的协议笔记 |
| `docs/指纹.md`、`CdpFingerprint`、Camoufox | 每浏览器一套指纹，文档写明目的是同机多账号不被站点关联 |
| `impersonate` | 把 HTTP 客户端的 TLS/JA3/JA4 伪装成浏览器，文档写明用来过 WAF 后纯 HTTP 接力 |
| `docs/逆向增强.md` 与 `examples/reverse/` | 断点偷页面里的 key、打掉反调试、抓包后改字段重放；并带 YouTube `yt_dl`（算 sig/n、下视频）和人人视频签名重放 |
| `examples/sites/douyin_*` | 以抖音 `a_bogus` 为目标吐环境、连续听 feed |
| `docs/差异化路线.md` 的账号池 / 指纹一致性 | 产品叙事是规模化多账号调度、对抗风控失败原因（`captcha` / `rate_limited`） |

默认 feature 只有 `cdp`，OCR、滑块、签名器、TLS 伪装是关着的。这降低了「装上就能用」的面，但**不改变公开提供**的事实：源码、示例和文档都在 GitHub / GitCode / docs.rs（`all-features = true`）。

## 2. 法条怎么套到这些能力上

国内看三套，由重到轻。

### 2.1 专门工具：网络安全法第 27 条、刑法第 285 条第 3 款

网络安全法第 27 条禁止**提供专门用于**侵入网络、干扰防护措施、窃取网络数据的程序和工具；明知他人做这类事还提供技术支持，同样禁止。未入刑时，第 63 条仍可由公安机关没收违法所得，并处罚款、拘留。

刑法第 285 条第 3 款是同一事实的刑事版：提供专门用于侵入、非法控制计算机信息系统的程序、工具，情节严重的，处三年以下有期徒刑，并处或单处罚金。最高人民法院、最高人民检察院 2011 年《关于办理危害计算机信息系统安全刑事案件应用法律若干问题的解释》第 2 条把「专门」定义成：

- 能避开或突破安全保护措施，**未经授权**获取数据；或
- 能避开或突破安全保护措施，**未经授权**控制系统；或
- 其他专门设计用来侵入、非法控制、非法取数的程序、工具。

第 3 条的「情节严重」包含：向他人提供这类工具二十人次以上，或违法所得五千元以上。「人次」算的是提供次数，不要求你认识使用者。公开仓库被克隆、Release 被下载，一旦工具被认定成「专门」，人次门槛并不高。

通用自动化（点击、填表、读自己有权访问的页面）对不上「专门」。对得上的是：**验证码求解、Turnstile 出 token、指纹伪装用来躲关联、TLS 伪装用来躲 WAF、把别人的签名算法抠出来脱浏览器重放。** 这些功能的设计目的就是避开站点的安全保护措施。文档和示例把对象写死（易盾、Turnstile、抖音 `a_bogus`、YouTube sig），等于把「专门」写在纸面上。

「学习研究」「开源」「用户自己负责」不是这条规定的免责事由。研究例外若存在，也要求对象是你有权测试的系统，并且**不向公众提供**避开措施的技术。

帮助信息网络犯罪活动罪（刑法第 287 条之二）门槛更高，要「明知」他人在利用信息网络犯罪。公开卖「过盾 / 养号」或在别人已经用这套去撞库、盗号之后还继续供工具，才会靠近这一条。现在优先处理的是第 285 条第 3 款和第 27 条，不要等「明知」成立。

### 2.2 著作权技术措施：YouTube 下载器、签名直链

著作权法（2020）第 50 条：未经许可，不得故意避开或破坏权利人为保护著作权采取的技术措施。该条的科研教学例外写明：**不得向他人提供**避开技术措施的技术、装置或部件。

`yt_dl` / `re_yt_*` 的用途是算出播放签名、拿出直链、下载合并。这是在向仓库访问者提供避开 YouTube 技术措施的实现。人人视频那条「签名复现后重放、拿到可播内容」是同一类。民事侵权成立不需要你自己去商用传播片子；把能用的绕过做到公开示例里就够了。

### 2.3 用这套去规模化采集时，使用者（以及代运营的我们）另外触线

这些不因为「框架作者」三个字自动落到头上，但**谁跑业务谁承担**：

- **个人信息保护法**：页面里的头像、昵称、评论、手机号是个人信息。没有法定事由或单独同意就批量处理，违法的是处理者。框架只提供点击时，处理者是跑脚本的人；极数本源若代客户跑、或自己把数据入库，处理者就是我们。
- **数据安全法、反不正当竞争**：破技术措施批量拿走他人经营数据，民事案件里已经多次被认定构成不正当竞争（点评、微博、短视频一类）。`robots.txt` 只是合规信号，不是免责凭证。现在的 LICENSE 把 robots 写成唯一红线，范围太窄。
- **账号**：批量注册、买卖、出租账号，以及用指纹池维持「看起来像很多人」的账号矩阵，平台规则禁止，情节上去还会碰到账号管理规定和诈骗、刷量类案件。`docs/差异化路线.md` 若对外就讲「对抗风控的养号运行时」，产品本身会被当成专门工具的使用说明。

境外站点（Cloudflare、YouTube、exa.ai）还有对方所在地的计算机滥用法和平台条款。示例里已经对真实第三方打出过 Turnstile token 并走到发信流程。那是**已经发生的访问**，不只是代码摆在那里。

## 3. 现在这张「免责」挡不住什么

`LICENSE` 和 README「负责任使用」有用，但是辅助。它们挡不住的是：

- 刑事责任和行政责任不能用格式条款约定掉。
- 「违法则授权自动失效」只约束版权许可，不抹掉已经提供工具的事实。
- 「与版权持有人无关」在使用者损害第三人时，法院仍看你是否提供了专门工具、是否宣传过这种用法、是否收费。条款写得越绝对，越不像认真设过使用边界。
- 非商业许可管的是**别人能不能拿去卖**。作者自己公开分发，照样算「提供」。不收费也不能避开「二十人次」。

CSDN 0.6.2 稿的口径是对的：只讲运行时，并写明不要绕登录、验证码、付费墙。GitHub 上的 `docs/CF协议过.md`、`docs/逆向增强.md` 和易盾示例是相反口径。对外以哪份为准，执法和对方律师会选对自己有利的那份。

## 5. 要怎么做

原则：**公开的只有运行时；站点级绕过只留在私有、且只对书面授权的目标。** 不靠再写一段更长的免责声明。

### 本周（公开面）

1. 停止对第三方生产环境打验证码、盾、签名。易盾采集（`YIDUN_HARVEST`）、`auth.exa.ai` 过盾、YouTube / 人人视频下载、抖音签名吐环境，都不再作为开发例程跑。
2. 从公开分支挪走站点级产物，放到不公开的仓库：`examples/clickword/`、`examples/cloudflare/`、`examples/reverse/` 里的 `yt_*` 与 `re_rrmj*`、`examples/sites/douyin_*`，以及 `docs/CF协议过.md`、`docs/CDP过盾.md`、`docs/逆向增强.md` 里的实战步骤、`docs/OCR模型热替换.md` 的易盾管线。通用能力（CDP、`tab.agent()`、Profile、网络观察、可选的通用 OCR）留在公开仓库。
3. 知道历史提交和已有 fork 删不掉。要做的是：默认分支不再提供、Release note 写明这些示例不再维护、不再宣传。不要为了「洗历史」去 `filter-repo`，那会弄坏协作者，也抹不掉别人已经拉走的副本。
4. `Cargo.toml` 关键词改为浏览器自动化本身，例如 `browser`、`cdp`、`automation`。`description` 不再出现过盾、反检测。
5. 对外文章只保持 CSDN 0.6.2 那种口径。内部设计文档可以写能力边界，不写「对某站如何打出 token / 如何下视频」。

### 产品边界（在挪代码的同时定死）

公开承诺只做三件事：

- 控用户自己机器上的浏览器；
- 账号、Profile、失败冷却、审计账本（客户**自己的**账号，用来少误伤、能复盘）；
- 在书面授权范围内做测试和流程自动化。

不作为功能、不作为案例、不作为收费项的事：

- 过某家验证码、过某朵云的盾、批量养号、指纹对抗风控、脱浏览器复现他人签名、替客户「拿难获取的数据」。

`identity-job` 可以留。对外说法改成：客户声明这些账号是自己的；账本用来限速、熔断、事后解释为什么停。不要出现 `scrape_aggressive` 这种对外预设名，除非预设的内容是更严的限速而不是更猛的采集。

收费的时候合同里写清：客户保证对目标系统有授权；发现是在绕过他人技术措施则停服；我们不提供「保证过某站」的验收标准。验收标准用运行时指标（开页、snapshot、Profile 租约、账本），不用过盾成功率。

### 许可证

保留 source-available、商用需书面授权。改三处措辞：

- 写明本许可**不授权**避开他人技术措施、未经授权访问、绕过验证码或付费墙、采集无权处理的个人信息。
- 删掉「一切纠纷与版权人无关」这种绝对免责，改成：许可不构成对任何第三方站点的授权；使用者对自己的行为负责。
- 商用授权文本单独一份，把上面的禁止事项写成合同义务，而不是只写「先付钱」。

### 找律师时直接问的四句

1. 以当前公开仓库的示例和文档，第 285 条第 3 款和第 27 条的「专门工具」是否已经具备认定基础；挪走站点级示例之后，剩下的通用 CDP 运行时是否还构成。
2. `yt_dl` 公开过，著作权第 50 条的侵权是否已经完成；下架后还要不要主动通知已发布的 Release。
3. 若只向签约客户、且合同写明授权测试，私有交付滑块距离或 TLS 指纹，边界在哪里。
4. 极数本源自己的采集业务（若有）谁是个人信息处理者，要不要单独做合规，而不是靠框架许可证。

## 6. 不要做的事

- 不要再给公开示例加新的站点适配（下一家验证码、下一家短视频签名）。
- 不要把「过盾成功率」写进对外材料或合同验收。
- 不要以为可选 feature、或 README 第六条「别绕验证码」，就能抵消同仓库里的可运行过盾示例。
- 不要在出事前用销毁本地样本代替上面的公开面处理。该停的是继续采集和继续公开。
